# S2 Clear HUD 0.1.1 — Readable Ammo Count

Molkerr reported in
[S2Tweaker #9](https://github.com/Zayn995/S2Tweaker/issues/9#issuecomment-5734833722)
that the ammo count reads as black and is almost invisible, because the game
itself is dark.

## What happened

0.1.0 replaced all 33 target textures with fully transparent pixels. Two of them
sit behind the ammo readout: `T_Ammo_Back_Full`, the panel, and
`Texture_Back_Shade`, its shade. The digits themselves are not among the replaced
textures — the game draws them — so the mod never recoloured the count. It
removed the panel the game's dark digits relied on for contrast.

## What changes

- **The ammo panel is now a faint generated plate** instead of being removed, so
  the digits keep something to sit on. The shade stays removed.
- **The other 31 backgrounds and the amber selection marker are byte-for-byte
  what 0.1.0 produced.** A test pins those payloads so the clear look cannot
  drift while the plate is being tuned.
- **`--plate TEXTURE=R,G,B,A`** builds a different colour without editing the
  code, and `0,0,0,0` removes a background as before.

All plate pixels are generated by the build, as before. No pixels are copied out
of the game's textures.

## The plate colour is a first guess

The shipped plate is a light warm grey at about 47% alpha, chosen from the
report: a count described as black needs a lighter backing, not a darker one.
Nobody has seen it in the game yet, and the two ammo textures were never
inspected visually, so the colour may well be wrong — too heavy, or the wrong
direction entirely if the digits turn out to be light rather than dark.

Comparing takes one build each:

```powershell
python build.py ... --plate T_Ammo_Back_Full=216,214,206,120   # the shipped light plate
python build.py ... --plate T_Ammo_Back_Full=0,0,0,90          # a dark plate instead
python build.py ... --plate T_Ammo_Back_Full=0,0,0,0           # removed, as in 0.1.0
```

If the dark plate is the readable one, the digits are light and the shade was the
layer doing the work; switching `PLATES` in `build.py` to that colour and
restoring the shade would be the better fix.

## Validation

The payload generators are checked by 16 tests that decode every generated
payload back and require it to be exactly the intended colour, including the
BC7 bit layout, the uncompressed channel order, the rejection of a translucent
DXT1 plate and the malformed `--plate` inputs. They need no game installation:
`python tests/test_pixels.py`.

The build's own checks are unchanged apart from being stricter: read-back now
compares every texture's pixels against the exact generated bytes rather than
re-deriving them.

**Not play-tested.** No game session was started. Startup, rendering and how
heavy the new plate looks remain unconfirmed.
